# 팜싱크 (FarmSync)

**신호가 끊겨도 납품 주문은 끊기지 않게 하는 클라이언트–서버 채팅 프로그램**

농장주와 기업 구매담당자가 납품을 협의하는 채팅 앱입니다. 산간 농가처럼 회선이 불안정한 환경에서도
대화가 **유실되지 않고, 중복되지 않고, 순서가 뒤바뀌지 않도록** 애플리케이션 레벨에서 보장합니다.

컴퓨터네트워크 기말 프로젝트 — OSI 7계층을 코드와 로그로 증명하는 것을 목표로 합니다.

---

## 왜 만들었나

농촌·산간 지역은 통신 인프라가 부족해 인터넷이 자주 끊깁니다. 납품 협의는 돈이 오가는 대화라서
메시지 하나가 사라지거나 순서가 뒤바뀌면 실제 손실이 납니다. 그런데 **TCP는 연결이 끊긴 동안
애플리케이션이 보내려던 메시지의 존재를 모릅니다.** 그래서 로컬 큐와 수신 오프셋을 응용·세션
계층에 두었습니다.

## 구조

```
 [농장주 앱]                [중앙 서버]                 [기업 담당자 앱]
 ┌──────────┐            ┌──────────────┐            ┌──────────┐
 │ 채팅 UI  │            │ ① 세션 관리자 │            │ 채팅 UI  │
 │ 로컬 큐  │◄─WebSocket─┤ ② 이력 저장소 │─WebSocket─►│ 로컬 큐  │
 │ 수신 오프셋│  (TCP 위)  │ ③ 전역 순번   │  (TCP 위)  │ 수신 오프셋│
 │ 상태 표시 │            │ ④ 동기화 관리 │            │ 상태 표시 │
 └──────────┘            └──────────────┘            └──────────┘
```

| 구성 | 책임 |
|---|---|
| 농장주 앱 / 기업 앱 | 채팅 UI, **로컬 큐(Outbox)**, **수신 오프셋**, 메시지 상태 표시 |
| 중앙 서버 | **세션 관리**, **이력 저장**, **전역 순번 발급**, **동기화 관리** |

**왜 P2P가 아니라 클라이언트–서버인가**

1. 양쪽이 동시에 보내면 누가 먼저인지 정할 **권위자**가 필요하다 (전역 순번)
2. 상대가 오프라인이면 대화를 **보관할 주체**가 필요하다 (이력 저장소)
3. 동기화 기준점(마지막 수신 오프셋)을 대조할 **중립 저장소**가 필요하다

## 핵심 메커니즘 3개

| # | 메커니즘 | 구현 위치 | 막아주는 문제 |
|---|---|---|---|
| 1 | **로컬 큐 (Outbox)** | `web/assets/js/sync-core.js` | 끊긴 동안 작성한 메시지가 사라짐 |
| 2 | **수신 오프셋 재동기화** | `sync-core.js` + `server/store.py:since()` | 못 받은 구간이 영구히 비어 있음 |
| 3 | **멱등성 (cid 중복 방지)** | `server/store.py:append()` `UNIQUE(room, cid)` | 재전송이 중복 주문이 됨 |

### 3번이 왜 필요한가

메시지를 보내고 `DELIVERED` 를 받기 직전에 연결이 끊기면 클라이언트는 **보냈는지 알 수 없습니다.**
안 보내면 유실, 무조건 다시 보내면 중복 — 이 딜레마를 푸는 것이 멱등성입니다.
모든 메시지에 클라이언트가 만든 고유 ID(`cid`)를 붙이고, 서버는 같은 `cid` 를 두 번 저장하지 않습니다.

```
상황: 클라이언트가 SEND(cid=A1) 전송 → 서버는 저장 → DELIVERED 전송 중 연결 끊김
결과: 클라이언트는 A1 을 재전송
      서버는 (room, cid=A1) 이 이미 있으므로 새 행을 만들지 않고 기존 seq 를 돌려줌
      → DELIVERED {duplicate: true} · 서버 이력에는 정확히 1건
```

## 프로토콜 (7계층 응용 계층)

| 방향 | 타입 | 의미 |
|---|---|---|
| C → S | `HELLO` | 접속 + **내가 어디까지 받았는지**(`last_seq`) 알림 |
| C → S | `SEND` | 메시지 전송 (`cid` = 멱등성 키) |
| C → S | `READ` | 읽음 표시 |
| S → C | `WELCOME` | 세션 ID 발급, 접속자 목록 |
| S → C | `SYNC` | 밀린 구간 일괄 전송 (`from_seq` ~ `to_seq`) |
| S → C | `MSG` | 새 메시지 (서버가 부여한 전역 순번 포함) |
| S → C | `DELIVERED` | 저장 완료 통보 (`duplicate` 플래그) |
| S → C | `PRESENCE` | 접속 / 접속 종료 |
| S → C | `EVENT` | 계층 로그용 서버 이벤트 |

메시지 상태 표기

| 표시 | 뜻 |
|---|---|
| `◷ 대기 중` | 로컬 큐에 있음 (아직 못 보냄) |
| `↻ 전송 중` | 보냈지만 서버 확인을 못 받음 — 재접속 시 재전송 |
| `✓ 서버 저장` | 서버가 순번을 부여해 저장함 |
| `✓✓ … 읽음` | 상대가 읽음 표시를 보냄 |
| `중복 차단` | 같은 `cid` 재전송 — 새로 저장되지 않음 |

## OSI 7계층 대응

| 계층 | 구현 |
|---|---|
| **7 응용** | `HELLO` · `SEND` · `SYNC` · `DELIVERED` · `READ` 규약, 메시지 상태 관리 (`server/protocol.py`) |
| **6 표현** | JSON 직렬화 + UTF-8, 밀린 묶음 전송 (`protocol.py:encode/decode`) |
| **5 세션** | 세션 ID, **수신 오프셋**, 재접속 복구, 접속자 관리 (`app.py` + `store.py`) |
| **4 전송** | WebSocket over **TCP** — 순서 보장·재전송. **끊기면 그 지점까지가 한계** |
| **3 네트워크** | 서버 IP까지의 라우팅, LTE ↔ Wi-Fi 전환 (코드 밖 / OS) |
| **2 데이터링크** | 무선 프레임·MAC 주소 (코드 밖) |
| **1 물리** | 산간 약전계 신호 — 단절의 근본 원인 (코드 밖) |

> **"TCP가 재전송하는데 왜 또 구현했나"** — TCP는 **연결이 살아있는 동안만** 재전송합니다.
> 연결이 끊기면 애플리케이션이 보내려던 메시지의 존재 자체를 TCP는 알지 못합니다.
> 그래서 큐와 오프셋을 7·5계층에 둡니다. 이것이 이 프로젝트가 7계층을 모두 설명할 수 있는 이유입니다.

`lab/` 폴더에는 같은 개념을 **raw TCP 소켓**으로 구현한 최소 예제가 있어 4계층을 직접 보여줄 수 있습니다.

## 실행

```bash
# 1) 의존성
pip install -r requirements.txt

# 2) 서버 실행 (홈페이지 + 채팅앱 + WebSocket 을 한 프로세스로 서빙)
uvicorn server.app:app --reload --port 8000
```

| 주소 | 내용 |
|---|---|
| `http://localhost:8000/` | 소개 페이지 (홈페이지) |
| `http://localhost:8000/app` | 채팅 앱 |
| `http://localhost:8000/healthz` | 헬스체크 |
| `http://localhost:8000/api/stats?room=default` | 실증 지표 (JSON) |
| `http://localhost:8000/api/history?room=default` | 서버 이력 (JSON) |

**두 사용자로 시연하려면** 브라우저 창 두 개를 열고 한쪽에서 접속자를 `기업` 으로 바꾸면 됩니다.
(`/app?user=기업`)

## 테스트

```bash
# 저장소 단위 테스트 (멱등성 · 전역 순번 · 수신 오프셋)
python -m pytest tests/test_store.py -v

# 클라이언트 동기화 코어 테스트 (Node 내장 러너, 의존성 없음)
node --test tests/sync-core.test.mjs

# 종단 간 오프라인 재동기화 시연 + 검증
python scripts/demo_offline.py
```

`scripts/demo_offline.py` 는 실제 서버를 띄우고 다음을 재현한 뒤 판정까지 출력합니다.

1. 정상 대화
2. 클라이언트 A 회선 강제 단절
3. A 로컬 큐 3건 적재, B 는 정상 발신
4. A 재접속 → 수신 오프셋 대조로 밀린 구간만 복구
5. 같은 `cid` 로 의도적 재전송 → 중복 차단 확인
6. **유실 0 · 중복 0 · 순서 오류 0** 검사

## 배포

### 방법 1 — Docker (권장)

```bash
docker compose up --build -d      # http://localhost:8000
```

`docker-compose.yml` 은 메시지 DB 를 named volume 에 두어 컨테이너를 재생성해도 이력이 유지됩니다.

### 방법 2 — Render.com 무료 플랜

`render.yaml` 이 저장소에 포함되어 있습니다. Render 대시보드 → **New → Blueprint** → 저장소 선택 → 배포.
(무료 플랜은 일정 시간 미사용 시 잠들고, 첫 요청에 깨어납니다.)

### 방법 3 — Railway / Fly.io / VPS

시작 명령만 지정하면 됩니다.

```bash
uvicorn server.app:app --host 0.0.0.0 --port $PORT
```

`Dockerfile` 이 `$PORT` 를 자동으로 사용합니다.

### 환경 변수

| 이름 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `8000` | 서버 포트 (클라우드가 주입) |
| `FARMSYNC_DB` | `./data/farmsync.db` | 메시지 DB 경로 |
| `FARMSYNC_SYNC_BATCH` | `1000` | 한 번에 내려주는 최대 재동기화 건수 |

> **주의** — 무료 플랜의 로컬 파일 시스템은 재배포 시 초기화될 수 있습니다. 이력을 영구 보관하려면
> `data/` 를 영구 볼륨에 마운트하거나 저장소를 외부 DB 로 교체하세요. `server/store.py` 의 인터페이스만
> 유지하면 교체가 쉽습니다.

## 발표용 시연 시나리오 (2분)

| 단계 | 조작 | 보여주는 것 |
|---|---|---|
| ① | 창 두 개로 접속 (농장주 / 기업) | 클라이언트–서버 구조 |
| ② | 서로 메시지 몇 개 교환 | 정상 동작, `✓ 서버 저장` + seq |
| ③ | 농장주 창에서 **회선 끊기** 클릭 | 오프라인 전환, 자동 재접속 중단 |
| ④ | 끊긴 상태에서 3건 입력 | **`◷ 대기 중`** — 메시지가 로컬 큐에 쌓임 |
| ⑤ | 기업 창에서 2건 전송 | 서버는 계속 동작 |
| ⑥ | **회선 복구** 클릭 | `재동기화: 수신 오프셋 43 → 45 · 밀린 2건 병합` 로그 → 밀린 대화가 순서대로 나타남 → 큐 3건 자동 발송 |
| ⑦ | 계층 로그 패널 지목 | L4 · L5 · L6 · L7 이 각각 무슨 일을 했는지 |
| ⑧ | 실증 지표 지목 | 유실 0 · 중복 0 · 순서 오류 0 |

마무리 멘트: **"지금 회선을 끊었습니다. 메시지는 사라지지 않았습니다."**
